# Интеграция LLM и разбор ответов

Слой провайдера не зависит от формата SAST и алгоритма чтения исходников.

| Файл | Ответственность | Что изменять |
|---|---|---|
| `providers/litellm.py` | HTTP, авторизация, повторы, таймаут | Транспорт или авторизацию |
| `providers/request.py` | Сборка сообщений и native tools | Поля запроса провайдера |
| `providers/response.py` | Извлечение сообщения из оболочки API | Другой формат вместо `choices[0].message` |
| `providers/parsers.py` | Декодирование в `{action, arguments, ...}` | Новые маркеры и синтаксис команд |
| `prompt.txt` | Инструкции аналитика и примеры команд | Политика taint-flow без правок транспорта |

**Путь сообщения:** ядро собирает контекст → `build_payload` → `LiteLLM.ask()` → `extract_message` → `parse_command` → `read`/`find` либо валидация `final` → событие JSONL.

**Форматы:** строгий JSON, JSON в Markdown, OpenAI `tool_calls`, маркеры `<|tool_call>` и ограниченный JSON-подобный синтаксис (ключи без кавычек и некоторые неверные escape). Парсер извлекает известные поля, но **не исполняет текст**, не придумывает пути и не запускает исходники. Неоднозначные команды отклоняются и пишутся в trace.

**Быстрая адаптация:** добавьте ветку парсера и тест с реальным ответом модели; сохраняйте явную ошибку при неоднозначности. При изменении `request.py` синхронизируйте примеры `prompt.txt` и оболочку `response.py`. Не публикуйте секреты из trace.
