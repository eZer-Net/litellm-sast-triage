# Архитектура

Проект разделяет CLI, исследование исходников, HTTP-транспорт провайдера, декодирование ответа ИИ и нормализацию SAST. Фиксированной директории `workspace/` больше нет.

```text
litellm-sast-triage/
├── agent.py                         # Точка входа Python
├── .env.example                     # Шаблон параметров окружения
├── prompt.txt                       # Редактируемые инструкции анализа безопасности
├── install.sh                       # Установка и подготовка окружения
├── Dockerfile / compose.yaml        # Запуск в контейнере
├── README.md / LICENSE              # Основной README и лицензия MIT
├── output/                          # Результаты JSON, Markdown и журнал JSONL
├── src/sast_triage/
│   ├── cli/main.py                  # Флаги, ввод пути к проекту, сохранение отчётов
│   ├── core/triage.py               # Цикл триажа, доказательства и лимиты
│   ├── core/trace.py                # Диагностика каждого обращения к модели
│   ├── source/explorer.py           # Чтение, поиск, карта функций и кеш
│   ├── source/tools.py              # Маршрутизация инструментов только для чтения
│   ├── parsers/sast.py              # Нормализация входных результатов SAST
│   └── providers/
│       ├── litellm.py               # HTTP-клиент, повторы и интервалы
│       ├── request.py               # Формирование запроса к провайдеру
│       ├── response.py              # Обработка ответа провайдера
│       └── parsers.py               # Гибкий разбор команд модели
├── docs/en/ + docs/ru/             # Документация для разработчиков и пользователей
└── tests/                            # Модульные и регрессионные тесты
```

**Точки расширения:** формат сканера меняется в `parsers/sast.py`; оболочка API — в `providers/{request,response}.py`; синтаксис команд модели — в `providers/parsers.py`. Ядро `core/triage.py` не зависит от исходной схемы JSON конкретного сканера.
