# Диагностика взаимодействия с LLM

При `TRACE_ENABLED=true` создаётся `output/<имя-отчёта>.trace.jsonl`. Одна строка — одно JSON-событие со временем UTC и номером алерта.

| Событие | Что сохраняется |
| --- | --- |
| `initial_evidence` | Переданный алерт, точный код Semgrep, контекст и карта символов |
| `llm_request` | Сообщения, отправленные модели, без HTTP-заголовка авторизации |
| `llm_response` | Ответ ассистента, реально полученный от LiteLLM |
| `parse_result` | Успех разбора и команда или тип/текст ошибки |
| `tool_result` | Аргументы `read`/`find` и полученные блоки кода |
| `action_rejected` | Отклонённое действие и причина |
| `final_accepted` | Принятый итоговый вердикт |
| `alert_finished` | Статус, причина, использованная глубина |
| `api_error` | Транспортная ошибка без ключа |

## Анализ ProtocolError

Найдите записи с нужным `alert_id` и сопоставьте `llm_response` с `parse_result`. Для нового формата команд меняйте `src/sast_triage/providers/parsers.py`, для структуры HTTP-ответа — `providers/response.py`, для запроса — `providers/request.py`.

## Безопасность

Трасса может содержать закрытый код и данные модели. Файл создаётся с правами 0600 на POSIX и игнорируется git. `TRACE_INCLUDE_CONTENT=false` скрывает текстовое содержимое; `TRACE_ENABLED=false` отключает трассу. Перед передачей журнала третьим лицам проверяйте его на секреты: встроенное маскирование не гарантирует удаления всех секретов.
