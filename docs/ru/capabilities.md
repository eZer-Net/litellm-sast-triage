# Ядро триажа: механизмы проверки доказательств

CLI помогает небольшим моделям и моделям с нестабильным протоколом анализировать SAST-находки. Механизмы повышают проверяемость, но **не гарантируют правильный статус и не доказывают эксплуатацию формально**.

| Механизм | Эффект |
|---|---|
| Точные координаты сканера | Отправка фактической строки Semgrep и ближайшего контекста |
| Карта Python-символов | Опорные точки функций и классов для адресного чтения |
| Адаптивные `read` / `find` | Малые файлы целиком, большие — ограниченными блоками |
| Приоритет текущего файла | Сначала поиск символов в файле текущего алерта |
| Кэш изученного кода | Отказ от повторного чтения диапазонов без нового содержимого |
| Бюджеты поиска и ходов | Ограничивают циклы модели и вынуждают зафиксировать итог |
| Терпимый парсер ответа | Понимает разные форматы вызовов, сообщает о неоднозначности |
| Проверка source/sink | Подтверждает, что указанные `file:line` действительно были отправлены модели |
| Проверка CWE для TP | Выявляет подмену класса уязвимости и недостающие guards/передачи данных |
| Нейтральное восстановление | Запрашивает доказательства, а не принуждает менять `TP` на `FP` |
| Диагностика JSONL | Сохраняет запросы, ответы, ошибки парсинга и действия инструментов |
| Постепенная запись | JSON и Markdown сохраняются после каждого алерта |

**Граница достоверности:** наличие ссылки `file:line` не равно доказанному ребру taint-flow. Для сложного случая допустим `NEEDS_REVIEW`.
